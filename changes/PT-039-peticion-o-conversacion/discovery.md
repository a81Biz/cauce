# PT-039 — Descubrimiento   `PHASE 2` · `FDGE-R42`

No hay ningún punto del marco donde se pregunte **qué es** un mensaje. `CORE.md` abre mandando
consultar el tablero (`SUITE-R49`), y consultar el tablero **ya es tratar el mensaje como
trabajo**.

## Los dos fallos simétricos

```
duda tratada como orden   → abre allocation, gasta compuertas, ensucia el tablero
orden tratada como charla → el trabajo no existe en ninguna parte
```

Los dos han ocurrido en esta sesión. El segundo es el que motivó `SUITE-R44`.

## Lo que ya existía y no se usaba para esto

`FDGE-R53` exige a **todo** intake una condición de terminado observable. Esa exigencia es
exactamente el criterio que separa una petición de una conversación: **si no se puede escribir
«termina cuando: …», no es una petición**. No hace falta inventar una prueba nueva.
