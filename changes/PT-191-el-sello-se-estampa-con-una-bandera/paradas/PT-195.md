## Qué paró

La limpieza de ramas del cierre de `EP-025`. Al mirar por qué existían **dos** proyecciones para la
misma persona —`cauce/alberto-martinez` publicada y `cauce/t` local— apareció la causa:

```
git config --local user.name    T
git config --local user.email   t@t
git config --global user.name   Alberto Martínez
git config --global user.email  alberto@a81.biz
```

La configuración **local del repositorio real** era la identidad del **arnés de pruebas**.

## El alcance, medido

- `tracker personas` ya lo declaraba: **`T <t@t>` · 10 commits · SIN DECLARAR**.
- Los **13 commits** de restos del arnés en `main` local son suyos.
- Y **los tres commits de esta misma sesión** —`fb10d3d`, `ff166bf`, `7e5ac32`— salieron firmados
  como `T <t@t>` en vez de como el firmante. Nadie lo advirtió al hacerlos.

```

  ( cd "$WORK" || { echo "FIXTURE SIN TERRENO: …" >&2; exit 90; }
    git config user.email t@t; git config user.name T
```

La guarda `|| exit 90` la puso `PT-188`. **Antes de `PT-188` no estaba**, y cuando ese `cd` fallaba
el `git config` se ejecutaba en el repositorio real. `PT-188` impidió que vuelva a ocurrir; **nadie
revirtió lo que ya había dejado puesto**, porque nada lo miraba.

## Por qué es una tarea y no sólo una limpieza

La limpieza es de la máquina y ya está hecha: `git config --local --unset` devuelve la identidad a
la global, que sí está declarada en `personas`. Eso no necesita tarea.

**Lo que sí la necesita es el hueco:** nada en el marco comprueba que la identidad con la que este
repositorio commitea corresponda a una persona declarada. `tracker personas` **lo enseña** —dice
«SIN DECLARAR» con su recuento— pero **ninguna compuerta lo lee**, así que un repositorio puede
firmar meses de trabajo con una identidad que no es de nadie y seguir en verde.

Es la forma que `PT-087` cierra en otros sitios: información correcta, calculada, y sin nadie que
la exija. Y su consecuencia es de las caras — `SUITE-R27` dice que lo que hace contrastable a una
firma es que el nombre esté en `firmantes`; un commit atribuido a `T <t@t>` no es contrastable
contra nada.

## Lo que NO se hace aquí

además ya están publicados. **No se declara `T <t@t>` en `personas`**: sería atribuir a una persona
los commits del fixture, que es exactamente el error contrario.
